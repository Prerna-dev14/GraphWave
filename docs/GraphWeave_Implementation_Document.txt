Implementation sequence and engineering details

Implement in small, verifiable increments. Do not generate the entire codebase in one unreviewed change. Each phase must end with tests, a build/run check, updated documentation, and a concise report.

Detailed request flow

Ingest document and preserve stable document, version, chunk, and provenance identifiers.

Extract entities and typed relationships using a schema-constrained adapter; validate types and source references.

Resolve canonical entities conservatively and write nodes/edges idempotently with provenance and scope.

Embed chunks and retrieve vector seed evidence for the question.

Expand bounded graph neighborhoods and paths from seed entities; filter all results by scope.

Fuse and deduplicate graph and vector evidence, rank it, and assemble a compact evidence bundle.

Generate answer with citations to source chunks and explain uncertainty when the evidence path is incomplete.

Configuration and environment

Provide .env.example with DATABASE_URL, REDIS_URL when used, model provider selection, model names, embedding model, API keys as blank placeholders, log level, and feature flags.

Validate required settings at startup and fail with actionable errors that do not print secret values.

Keep local defaults suitable for development only; document production secret management separately.

Provide deterministic fake model and embedding adapters for CI tests so the core suite does not require paid API calls.

Test strategy

Unit tests: normalization, policy decisions, metadata validation, ranking/fusion, error mapping, cost calculations, and schema validation.

Integration tests: PostgreSQL migrations, vector retrieval, Redis/Neo4j interactions where applicable, and API workflows.

Security tests: authorization boundaries, prompt injection handling, unsafe cache reuse, malformed payloads, and sensitive logging.

Evaluation tests: fixed dataset, baseline comparison, documented metrics, and regression thresholds.

Frontend tests: key dashboard states, validation, permission errors, empty states, and API error handling.

Smoke test: clean Docker Compose startup, health checks, sample ingestion, one query, and dashboard data.

Deployment and operations

Use Docker Compose for local development with health checks and persistent volumes where required.

Include migration and seed commands; avoid implicit schema changes on every request.

Set request timeouts and bounded retries; make ingestion jobs idempotent.

Document backup/restore expectations, data deletion, cache invalidation, logs/metrics, and known scaling limits.

Provide a demo script and troubleshooting section.
